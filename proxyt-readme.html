ProxyT

A lightweight proxy for the Tailscale control plane. Host it on your Pi or VPS, expose it via Tailscale Funnel or your own domain, and authenticate Tailscale clients even when login.tailscale.com is blocked or unreachable.

GitHub ↗ Docs ↗ 
Device on a network blocking tailscale.com
        │
        │  HTTPS (public internet)
        ▼
https://your-node.ibis-velociraptor.ts.net   ← Tailscale Funnel (TLS)
        │                — OR —
https://proxyt.yourdomain.com               ← Custom domain (Let's Encrypt)
        │
        │  HTTP (localhost only)
        ▼
ProxyT  :8080  --http-only                    ← proxyt serve
        │
        │  HTTPS
        ▼
login.tailscale.com                          ← Tailscale control plane

⚡ One-line Installer

Interactive script — detects arch, installs binary, writes config, creates systemd service.
Supports Funnel mode, custom domain (Let's Encrypt), and HTTP-only behind proxy.

# Download and run the installer
curl -sL https://raw.githubusercontent.com/YOUR_FORK/proxyt-install/main/install-proxyt.sh \
  | sudo bash

Or download and inspect before running: curl -sLO .../install-proxyt.sh && less install-proxyt.sh && sudo bash install-proxyt.sh

⚠ Enable HTTPS Certificates first. In the Tailscale admin console → DNS tab → HTTPS Certificates → Enable. Funnel will not work without this.

Step 1 — Grant Funnel in ACL Policy

In your Tailscale admin Access Controls, add the funnel nodeAttr. Since tailnet-pi77 carries tag:subnet-router, add it to that tag — or target the node directly.

ACL Policy — via existing tag (recommended)
"nodeAttrs": [
  {
    "target": ["tag:subnet-router"],
    "attr":   ["funnel"]
  }
]
ACL Policy — target node directly
"nodeAttrs": [
  {
    "target": ["tailnet-pi77"],
    "attr":   ["funnel"]
  }
]
2
Install ProxyT Binary

Pi 5 is aarch64 — use the arm64 build.

bash — tailnet-pi77
VERSION="v0.0.5"
curl -sLO "https://github.com/jaxxstorm/proxyt/releases/download/${VERSION}/proxyt_linux_arm64.tar.gz"
tar -xzf proxyt_linux_arm64.tar.gz
sudo install -m 0755 proxyt /usr/local/bin/proxyt
rm proxyt_linux_arm64.tar.gz proxyt
# Verify
proxyt --version
proxyt serve --help
3
Create Config File

bind: 127.0.0.1 locks ProxyT to loopback — only Funnel can reach it. Nothing on your LAN (172.16.10.0/24) can touch port 8080 directly.

bash
sudo tee /etc/proxyt.yaml > /dev/null <<'EOF'
domain: tailnet-pi77.ibis-velociraptor.ts.net
http-only: true
port: 8080
bind: 127.0.0.1
debug: false
EOF
sudo chmod 644 /etc/proxyt.yaml
/etc/proxyt.yaml
# ProxyT — Funnel mode (HTTP-only, TLS handled by Funnel)
domain:    tailnet-pi77.ibis-velociraptor.ts.net
http-only: true
port:      8080
bind:      127.0.0.1
debug:     false
4
Create systemd Service
bash
sudo tee /etc/systemd/system/proxyt.service > /dev/null <<'EOF'
[Unit]
Description=ProxyT - Tailscale control plane proxy
Documentation=https://proxyt.io
After=network.target tailscaled.service
Wants=tailscaled.service

[Service]
Type=simple
ExecStart=/usr/local/bin/proxyt serve --config /etc/proxyt.yaml
Restart=on-failure
RestartSec=5
StartLimitIntervalSec=60
StartLimitBurst=3
User=nobody
Group=nogroup
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
PrivateDevices=true
CapabilityBoundingSet=
AmbientCapabilities=
RestrictNamespaces=true
LockPersonality=true
RestrictRealtime=true

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now proxyt
sudo systemctl status proxyt

Confirm it's on loopback only:

ss -tlnp | grep 8080
# Expected: 127.0.0.1:8080   ← NOT 0.0.0.0:8080
curl -s http://localhost:8080
# Any HTTP response confirms proxyt is alive
5
Enable Tailscale Funnel
# Expose port 8080 publicly, persist in tailscaled state
sudo tailscale funnel --bg 8080

# Verify
tailscale funnel status

Expected output:

https://tailnet-pi77.ibis-velociraptor.ts.net (Funnel on)
|-- / proxy http://127.0.0.1:8080

Test from outside your tailnet (phone on mobile data):

curl -I https://tailnet-pi77.ibis-velociraptor.ts.net
6
Persist Funnel Across Reboots

--bg saves state inside tailscaled. Reboot and run tailscale funnel status to confirm. If it doesn't persist, add this unit:

bash — optional persistence unit
sudo tee /etc/systemd/system/tailscale-funnel-proxyt.service > /dev/null <<'EOF'
[Unit]
Description=Tailscale Funnel for ProxyT port 8080
After=tailscaled.service proxyt.service
Requires=proxyt.service

[Service]
Type=oneshot
ExecStart=/usr/bin/tailscale funnel --bg 8080
RemainAfterExit=yes
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable tailscale-funnel-proxyt
Custom domain mode: ProxyT handles TLS itself via Let's Encrypt. No Funnel needed. Your domain's A record must point to this server's public IP. Port 80 and 443 must be open.
1
Install ProxyT Binary
bash
VERSION="v0.0.5"
curl -sLO "https://github.com/jaxxstorm/proxyt/releases/download/${VERSION}/proxyt_linux_arm64.tar.gz"
tar -xzf proxyt_linux_arm64.tar.gz
sudo install -m 0755 proxyt /usr/local/bin/proxyt
rm proxyt_linux_arm64.tar.gz proxyt
2
Create DNS A Record

Point your domain to this server's public IP before starting ProxyT.

FieldValue
TypeA
Nameproxyt.yourdomain.com
ValueYour server's public IP
TTL300
Cloudflare users: Set DNS proxy to DNS only (grey cloud). Orange cloud (proxy) will intercept the Let's Encrypt HTTP-01 challenge and break cert issuance.
3
Open Ports 80 and 443
bash — ufw
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw status
4
Create Config File
/etc/proxyt.yaml — custom domain with Let's Encrypt
# ProxyT — Custom domain mode (Let's Encrypt TLS)
domain:     proxyt.yourdomain.com
email:      you@yourdomain.com
issue:      true
https-port: 443
port:       80
debug:      false
5
Create systemd Service
Custom domain mode runs as root — it needs ports 80/443 and write access to cert storage. This is unavoidable without a separate ACME client.
bash
sudo tee /etc/systemd/system/proxyt.service > /dev/null <<'EOF'
[Unit]
Description=ProxyT - Tailscale control plane proxy
Documentation=https://proxyt.io
After=network.target tailscaled.service
Wants=tailscaled.service

[Service]
Type=simple
ExecStart=/usr/local/bin/proxyt serve --config /etc/proxyt.yaml
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now proxyt
sudo systemctl status proxyt

Watch logs during first start to see cert issuance:

journalctl -fu proxyt
Once running, your login server URL is https://proxyt.yourdomain.com. Use this in tailscale up --login-server on all client nodes.

Configuring Tailscale Clients

Run on every other tailnet node that should authenticate via ProxyT. Replace the URL with your actual Funnel hostname or custom domain.

bash — basic node
sudo tailscale logout
sudo tailscale up --login-server https://YOUR-PROXYT-URL
bash — Pi subnet router
sudo tailscale logout
sudo tailscale up \
  --login-server https://YOUR-PROXYT-URL \
  --advertise-routes=172.16.10.0/24 \
  --accept-routes \
  --advertise-exit-node
bash — Oracle VPS exit node
sudo tailscale logout
sudo tailscale up \
  --login-server https://YOUR-PROXYT-URL \
  --advertise-exit-node
⚠ The Chicken-and-Egg Rule

The host running ProxyT must authenticate directly to Tailscale — never through its own ProxyT. If it used --login-server pointing to itself and lost auth, Funnel goes down and no client can re-authenticate. 

tailnet-pi77  ──── direct ────►  login.tailscale.com
     │
     └── Funnel ──► ProxyT ──► login.tailscale.com  (for all other nodes)

✗ NEVER:  tailnet-pi77  →  --login-server https://tailnet-pi77.ibis-velociraptor.ts.net

Verification Checklist

1
ProxyT running
sudo systemctl status proxyt
2
Loopback binding
ss -tlnp | grep 8080 → must show 127.0.0.1:8080
3
Local HTTP response
curl -so /dev/null -w "%{http_code}" http://localhost:8080 → any non-000
4
Funnel active
tailscale funnel status → shows Funnel on
5
Public HTTPS reachable (from outside tailnet)
curl -I https://YOUR-PROXYT-URL → HTTP response
6
Client auth works
sudo tailscale up --login-server https://YOUR-PROXYT-URL

Security Notes

RiskMitigation
Port 8080 exposed on LAN bind: 127.0.0.1 in config — loopback only
ProxyT running with excess privileges User=nobody + full systemd hardening in Funnel mode
This node using its own ProxyT for auth Never set --login-server on the ProxyT host itself
Funnel down after reboot Funnel state persisted in tailscaled; backup systemd unit available
ProxyT accessible from LAN in http-proxy mode Change bind: 0.0.0.0 back to 127.0.0.1 if Cloudflare Tunnel is local
